# Paper Visualizer 初版产品要求

## 1. 产品目标

把一篇论文转换成一个可独立打开的交互式 HTML 阅读器。它不是视频课程，也不需要播放时间线；核心目标是把论文拆成可阅读、可交互、可追溯的知识组件，让读者快速理解研究问题、方法、公式、实验、证据和相关工作。

## 2. 理想阅读体验

- 先在一分钟内理解论文研究问题、核心方法与关键结果，再按需深入。
- 页面以论文原图、表格、公式、派生流程图和关系图为主要信息载体，文字负责解释而不是占满页面。
- 内容按知识块组织，不机械复刻论文目录。
- 每个关键结论都能回到论文原文、对应章节或 PDF 页面。
- 页面信息紧凑，单张卡片通常能完整显示必要内容。

## 3. 页面结构

推荐的初版章节顺序：

1. 论文身份与核心问题
2. 一分钟速读
3. 核心问题与诊断框架
4. 方法和训练架构
5. 关键公式及变量追溯
6. 训练机制或解释性模拟
7. 实验结果与细粒度证据
8. Related Work 与研究演化

页面不再设置独立的“证据地图”或“论文出处”章节；来源追溯通过各内容组件内的“查看原文”和页码跳转完成。

## 4. 图、表与派生可视化

### 好的设计

- 直接展示论文中的关键原图和原表。
- Figure 和 Table 在主阅读区域显示完整 caption。
- 复杂方法同时提供派生流程图或架构图，帮助读者理解输入、状态、评估与更新关系。
- 派生图明确标为“派生图”，并注明依据的章节。
- 点击图中的节点或数据点，可以查看它在论文正文中的对应证据。
- 图表视觉元素直接承担信息表达，正文只保留必要解释。

### 不好的设计

- 页面主体几乎全是文字。
- 用大段总结替代论文原图、表格和公式。
- 同一个 caption 在图片下方、浮动卡片和派生图旁重复出现。
- 把表号、页码、指标来源等元信息塞进每个数据点或卡片标题。
- 为了显得丰富而添加论文没有支持的装饰图、指标或关联。

## 5. Caption 规则

- 论文 Figure 和 Table 的正式 caption 在对应主视觉下完整展示。
- 图片放大视图可以保留同一个正式 caption。
- 证据浮动卡片只展示相关原文和必要公式，不重复 caption。
- 派生流程图不重复旁边论文原图已经展示的 caption。

## 6. 卡片交互

### 好的设计

- 浮动卡片内容以论文对应原文为主，必要时附带公式。
- 卡片只保留两个圆形操作：关闭 `×` 和跳转 `↗`。
- 跳转按钮与关闭按钮并排放置。
- 跳转按钮直接打开对应论文或 PDF 页面，不显示“打开 PDF 对应页面”等长文字。
- 卡片尺寸紧凑，优先一次显示完整内容。

### 不好的设计

- 使用“42.5% 从哪里来”“论文出处”“Table 2 · p.3”等解释性标题占据卡片空间。
- 在原文之外追加生成式总结、背景说明或重复结论。
- 同一张卡片出现多个来源标签、页码标签和文字按钮。
- 点击后触发全页多处高亮，干扰当前阅读位置。

## 7. 原子命题与 Evidence

页面需要建立论文级证据层。基础单元包括：

- `claim`：论文明确提出的判断或结论。
- `evidence`：正文中支持该判断的原句或原段。
- `figure/table element`：图、表中的节点、曲线、行、列或数据点。
- `formula/variable`：公式及其变量定义。
- `citation`：Related Work 中被讨论的论文。

组件中的元素应与这些原子单元绑定。例如，某个实验数据点只有在正文明确分析过时才可以点击；点击后展示对应原文。正文未单独讨论的数据点保持普通展示，不创建 Evidence 卡片，也不附加表格 citation。

### 好的 Evidence

- 内容是论文原句或连续原段。
- 明确对应当前点击的视觉元素。
- 跳转到准确的论文页面或引用论文入口。
- 同一 Evidence 可以被图、表、公式等不同组件复用。

### 不好的 Evidence

- 用 LLM 重新生成英文句子并冒充论文原文。
- 仅把表格数值重新描述一遍。
- 为正文没有讨论的数据点批量生成解释。
- 把 caption、表格行和正文分析混合成一段无法区分来源的文本。

## 8. 公式与变量追溯

- 公式使用浏览器公式渲染，不使用代码框。
- 变量直接在公式内部可点击，不再在公式下方增加一排变量按钮。
- 点击变量后展示论文中的变量定义、必要上下文和对应公式。
- 弹出文本中的当前变量使用粗体突出。
- 公式、变量、定义、章节和使用位置建立稳定映射。

## 9. Related Work

Related Work 是独立阅读章节，不只是参考文献列表。

### 需要展示

- 本论文引用工作的研究溯源。
- 不同代表工作的研究对象、监督信号、评估对象和关键差异。
- 研究问题如何从基准、检索与导航、工作记忆、过程监督演化到本文问题。
- 以本文为中心的关系分组图，只展示正文明确说明了关系的工作。
- 点击论文节点后展示本文 Related Work 对该工作的原文描述，并提供论文入口。

### 关系图规则

- 中心节点是当前论文。
- 周围工作按“基础与继承、同问题前作、改进与对比、数据与评测”四类正文关系组织。
- 每条关系必须绑定当前论文中的连续原文 Evidence 和页码，不能根据参考文献题目推断。
- 每个类别不设数量上限；是否纳入只取决于关系是否明确、证据是否充分。
- 仅有背景性提及、批量引用或只出现在参考文献列表中的论文不进入关系图。
- 节点大小不表达引用量，除非系统获得了可靠引用数据并明确标注。
- 关系图与下方差异矩阵互补，不再保留重复的论文卡片墙。

### 调研流程

- 由专门的 Related Work agent 负责拆解引用链。
- 子 agent 可以分别核验论文元数据、原文描述和研究问题演化。
- 论文题目、年份、作者和链接需要经过论文参考文献或可靠学术来源核验。
- 页面中的卡片引用当前论文 Related Work 原文；综合比较放在主 panel 中。

## 10. 内容去重

- 一项信息只选择一个主要展示位置。
- 论文原图已有完整 caption 时，派生流程图和浮动卡片不再重复。
- 主页面展示总结；点击后展示原文；两者承担不同职责。
- 图已经表达的结构，不再用一整段文字复述。
- Related Work 关系图负责关系，差异矩阵负责比较，两者不重复论文列表。

## 11. 可追溯数据结构

后续系统可为每个知识单元维护以下字段：

- `id`
- `type`: claim / evidence / figure / table / formula / variable / citation
- `source_section`
- `source_page`
- `verbatim_text`
- `summary`
- `visual_targets`
- `related_items`
- `external_url`

其中 `verbatim_text` 与 `summary` 必须分开保存，交互卡片默认使用 `verbatim_text`。

## 12. 建议生成流程

1. 解析 PDF，抽取章节、正文、Figure、Table、caption、公式和参考文献。
2. 把正文拆解为原子 claim 与 evidence，并保存精确来源。
3. 选择适合快速阅读的论文原图、表格和公式。
4. 从论文结构生成必要的流程图、架构图、比较图和关系图。
5. 将图中节点、表格数据点和公式变量绑定到 evidence。
6. 由 Related Work agent 调研引用链并生成论文关系图与差异矩阵。
7. 生成单文件交互式 HTML。
8. 检查原文一致性、链接、caption、公式、交互、重复内容和移动端布局。

## 13. 初版验收标准

- 页面不是纯文字阅读器。
- 核心 Figure、Table、公式和派生图齐全。
- Figure 与 Table caption 完整且只在合适位置出现。
- 所有 Evidence 卡片均来自论文原文。
- 正文未讨论的数据点不可点击。
- 公式变量可以直接点击并追溯。
- 卡片仅有关闭和跳转两个圆形按钮。
- 没有全页关联高亮。
- 没有同一内容在原图、派生图和卡片中重复展示。
- Related Work 包含关系图、差异矩阵、研究演化和论文入口。
- 关键内容可以跳转到准确的论文位置。
