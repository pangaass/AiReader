# Paper Visualizer 项目全景、当前进展与新窗口交接

更新时间：2026-09-04

## 1. 整体想做什么

这个项目最终要做的，不是某一篇论文的展示页，也不只是一个 PDF 阅读器，而是一个**通用、可验证、可交互的科研论文理解工作台**：用户放入任意论文 PDF，系统自动解析论文、建立结构化知识与证据关系，再生成适合快速理解的交互式可视化页面；用户在 Electron 中一边看生成式讲解，一边核对论文原文，并且任何关键结论、方法步骤、公式变量、图表元素和相关工作都能回到准确的 PDF 位置。

理想状态下，系统应形成一条完整链路：

`论文 PDF → 结构解析 → Paper IR → 知识与证据建模 → 栏目叙事规划 → 图表和交互生成 → Electron 阅读 → 原文核验 → 论文内问答与跨论文研究`

它应当逐步成为个人科研阅读与文献理解环境，而不是只生成一份漂亮但无法核对的论文摘要。

## 2. 你过去对产品的核心期望

### 2.1 阅读目标

- 读者先在一分钟内理解论文为什么值得读、解决什么问题、使用什么方法、得到什么结果，再按需要深入。
- 页面不机械复刻论文目录，也不把所有内容都做成相同的文字卡片；应按照知识关系重新组织论文。
- 论文原图、原表、公式、派生流程图和关系图承担主要信息表达，文字只负责必要解释。
- 信息应紧凑、可浏览，避免大段摘要、重复 caption 和装饰性可视化。

### 2.2 可信与可追溯

- 所有关键结论必须绑定论文中的连续原文 Evidence、页码和坐标，不能把模型生成文本冒充论文原文。
- 图、表、公式、变量、方法节点和 Related Work 论文都应能点击；交互不能只停留在普通卡片。
- 正文没有讨论的数据点不应自动生成解释，证据不足时应明确显示无法回答或需要审核。
- 论文原图与系统派生图必须区分；派生内容需要记录依据。

### 2.3 通用系统，而不是样例特判

- 输入应支持本地 PDF 和公开 PDF URL，输出应由统一 Paper IR、Schema 和模板驱动。
- AWM、Attention 或 Scim 只是测试样例，运行时代码不能写死论文标题、ID、方法名或固定页码。
- 新论文不应通过人工修改源码才能生成；复杂情况进入审核，而不是靠猜测补齐。

### 2.4 Electron 产品形态

- 左侧是论文库和文章目录，中间是 Visualizer，右侧是原始 PDF；左栏可以隐藏。
- 用户可以打开单篇 PDF 或整个文件夹，并在应用中直接构建 Visualizer。
- 中间任意可关联元素被点击后，右侧 PDF 应跳页并高亮对应原文。
- 阅读设置和模型设置应在应用中完成；Token 只保存在本机安全存储中。

### 2.5 不同栏目应有不同讲述方式

- Related Work 应接近 Connected Papers 的关系图，但每条边必须由当前论文的引用语境支持。
- 方法部分应按照方法流讲述，并与论文原方法图联动。
- 研究任务、动机、训练与推理、实验、结果、分析、结论和局限也应采用符合各自问题结构的视觉语言，而不是复用同一种卡片墙。

### 2.6 科研任务通过 Harness 实现

- 可以吸收 SciREX、SciERC、QASPER、PaperQA、SciFact、Scim 等工作的**任务定义**，例如信息抽取、证据问答、主张核验、共指、引用语境和矛盾发现。
- 不应照搬这些论文提出的某个 RAG 或模型架构；实现继续使用可替换的 Harness、版本化 Schema、Worker、Verifier 和 Evidence 门禁。
- 流程需要可缓存、可重试、可中断恢复、可独立审核，不能依赖一次长对话成功完成。

## 3. 当前整体已经做到什么

### 3.1 通用生成流水线：主体已完成

- 已建立 `parse → model → content → visual → related → page → render → review` 流水线。
- 支持 PDF 文本块、章节、Figure、Table、caption、公式候选、引用和页面坐标解析。
- 已建立 Paper IR、Page Model、版本化 Schema、连续原文 Evidence 和阶段产物。
- 已实现 Lead → Worker → Verifier 的统一任务信封、内容哈希缓存、有限重试、失败 attempt 保留和人工 overlay。
- 已生成自包含单文件 HTML；模板不依赖特定论文名称或 ID。

### 3.2 可追溯论文可视化：核心能力已完成

- 一分钟速读、方法、公式、实验结果、论文原图/表和 Related Work 已可从结构化数据生成。
- Evidence 卡片、PDF 页码跳转、公式内部变量交互、论文图片放大与键盘操作已实现。
- 原文与生成式总结分开保存；论文原图与派生图具有不同来源标记。
- AWM 与 Attention 两篇结构差异明显的论文已经通过同一流水线和同一模板的完整验收。

### 3.3 Electron 阅读器：可运行原型已完成

- 已实现“论文库 / Visualizer / 原始 PDF”三栏界面，左栏可以完全隐藏。
- 支持打开 PDF、打开论文文件夹、切换论文、读取文章目录和在应用中构建 Visualizer。
- 卡片、公式、图表节点、图片、表格和引用能够驱动右侧 PDF 跳页与坐标高亮。
- 已加入主题、内容密度、默认侧栏、PDF 缩放、恢复上次论文、Endpoint、Token 和 Model 设置。
- Token 使用 Electron 系统安全存储；没有 Token 时仍可阅读已生成内容。

### 3.4 栏目感知叙事：P0 原型已完成

- 一分钟速读：问题 / 方法 / 结果三格。
- 研究任务：任务画布。
- 已有方法：可筛选、缩放、拖拽的研究溯源图。
- 本文动机：观察 → 缺口 → 设计要求因果链。
- 方法总览：横向方法流，并与论文原方法图联动。
- 方法拆解：纵向模块步骤流。
- 训练与推理：执行轨道。
- 实验设计：实验蓝图。
- 主要结果：结果账本。
- 消融与分析：诊断矩阵。
- 结论与局限：结论—边界图。

### 3.5 已完成的验证

- 基础流水线曾以 AWM 与 Attention 完成双论文端到端验收，Reviewer 为 0 blocker、0 warning。
- 当前全量 Python 测试为 120/120 通过；Electron 测试为 Node 5 项、Python 14 项通过。
- Scim 页面已验证 31/31 证据入口、5/5 图片入口、6/6 页码入口和 17/17 栏目面板可定位。
- 方法总览中的 4 个步骤可交互；悬停可同步高亮 2 张论文原方法图，点击可打开对应原文证据。

## 4. 当前处于什么阶段

项目已经越过“能不能从论文生成页面”和“能不能在 Electron 中联动原文”的阶段，当前处于：

**从可运行的通用原型，升级为真正以科研理解任务驱动的产品。**

现在已经有比较完整的工程骨架和 P0 交互原型，但“栏目展示不同”目前主要完成了页面模型和视觉组件层；下一阶段需要让 Harness 真正理解每个栏目要回答的问题，并稳定地产生高质量、可验证的栏目结构。

当前工作分支为 `feature/section-aware-literature-interactions`。本轮改动仍在工作区，尚未提交。

## 5. 还需要做什么

### 5.1 第一优先级：让栏目差异从布局进入语义任务

- 新增稳定的 `core-contribution` Harness，只识别论文真正的 Problem、Method、Dataset、Metric 和 Result，避免把 Related Work 或普通术语误当核心方法。
- 新增 `relation-and-coreference` Harness，合并方法别名、跨句实体和图文指代。
- 新增 `section-story` Harness，让任务图、因果链、方法流、实验蓝图和结果账本来自栏目级证据组织，而不只是把已有条目换一种 CSS 排版。
- 为不同论文类型设计降级策略：没有训练过程、没有消融、没有数据集或属于用户研究的论文，不应强行套用固定栏目。

### 5.2 第一优先级：深化图文与原文交互

- 当前方法步骤只能在整张论文方法图层面联动；后续应建立“步骤 → 原图局部区域 → 正文段落”的精确映射。
- 结果账本需要把主张、实验条件、数值、原表行列和正文分析连接起来。
- 公式需要更可靠的二维结构解析、变量定义消歧和跨公式复用。
- Related Work 需要在现有引用溯源图基础上补充差异矩阵、论文预览和更可靠的外部论文身份核验。

### 5.3 第二优先级：加入科研文献任务

- `evidence-qa`：论文内提问，输出答案、支持证据和证据不足状态。
- `claim-check`：判断论文主张是被支持、反驳还是仍不确定，并绑定实验与引用。
- 术语、符号、引用预览：点击时给出当前论文语境中的解释，而不是通用百科解释。
- 跨论文比较与矛盾发现：比较方法、数据、指标、实验条件和结论。
- 研究线程：把多篇论文组织为用户自己的研究问题和阅读路径。

### 5.4 产品化与质量

- 用更多类型论文验证通用性：理论论文、系统论文、生命科学论文、综述和无标准实验结构的论文。
- 为人工审核提供界面，而不是只依赖 JSON overlay。
- 完善大论文性能、后台构建进度、失败恢复、重复论文合并和库管理。
- 完成 Electron 打包、安装和发布流程；当前仍主要通过 `npm start` 运行开发版本。
- 建立栏目级质量评测：不仅检查链接存在，还要评价是否抓住论文核心、是否漏掉重要证据、是否把栏目关系讲对。

## 6. 建议的后续路线

1. 先实现 `core-contribution + relation-and-coreference + section-story`，把当前栏目组件接到真正的 Harness 输出。
2. 选择 4–6 篇不同类型论文做栏目级评测和失败案例分析。
3. 实现方法图局部联动、结果—实验条件联动和论文内 Evidence QA。
4. 再扩展跨论文比较、矛盾检测和研究线程。
5. 最后补齐审核界面、性能优化与 Electron 打包，形成可日常使用的桌面产品。
